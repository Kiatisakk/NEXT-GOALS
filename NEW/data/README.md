# ข้อมูลทดลอง MoneyFlow สำหรับ NEXT GOAL

ไฟล์ `moneyflow_sample_statement.csv` เป็น bank statement **สังเคราะห์** 30 รายการ วันที่ 1–30 ธันวาคม 2024 จาก [MoneyFlow](https://github.com/leotemtem/MoneyFlow/blob/main/sample_data/sample_statement.csv) โดยคง [MIT license](MONEYFLOW_LICENSE.txt) ของผู้สร้างไว้ในโฟลเดอร์นี้ ข้อมูลต้นทางไม่มีสกุลเงินระบุ จึงใช้ตัวเลขเป็น **หน่วยเงินตามต้นทาง** ไม่ใช่เงินบาท

SHA-256 ของ CSV ที่ใช้: `387e8179a9e109b99382105e39e22e88fb1085e38fae2c1eddf73e87a0e46d80`

สร้าง input ที่ตรวจยอดคงเหลือทุกแถวและรัน POC จากโฟลเดอร์หลัก:

```powershell
python NEW/data/make_moneyflow_fixture.py
python NEW/next_goal_dp.py --input NEW/data/moneyflow_dp_input.json --transfer 1000 --transfer-month 1 --transfer-day 16 --json
```

`moneyflow_dp_input.json` ที่สร้างไว้แล้วใช้รายการเงินเข้าออกทั้ง 30 รายการตาม CSV และอนุมานยอดเปิดจาก `Balance - Amount` ของแถวแรก ได้ 0 หน่วยเงิน ยอดปิดตาม CSV คือ 3,130.26 หน่วยเงิน ข้อมูลต่อไปนี้เป็น **สมมติฐานที่เพิ่มเพื่อทดสอบ** ไม่ได้มากับ MoneyFlow:

- เป้าหมายสองรายการ 1,500 และ 1,000 หน่วยเงิน พร้อมคะแนนความสำคัญที่กำหนดเอง
- เงินสำรองขั้นต่ำ 0 เพราะยอดเปิดของไฟล์เท่ากับ 0
- สถานการณ์รายจ่ายเพิ่ม 500 หน่วยเงินวันที่ 18 ความน่าจะเป็น 20% (สถานการณ์ปกติ 80%)
- ธุรกรรมโอนทดลอง 1,000 หน่วยเงินวันที่ 16

ผลที่ตรวจได้: ก่อนโอน POC เติมทั้งสองเป้าหมายเต็ม หลังโอน POC เติมเป้าหมายแรกเต็มและไม่เติมเป้าหมายที่สอง ทั้งสองแผนยังผ่านข้อจำกัดสภาพคล่องตามสมมติฐานที่ใส่ ตัวเลข `safe_transfer_limit` ของ POC วัดเพียงความเป็นไปได้ด้านเงินสดและ **ไม่ได้รักษาเป้าหมาย** ตามข้อบกพร่องที่ตรวจพบก่อนหน้า

นี่เป็นการทดสอบการอ่านข้อมูลและการทำงานของ solver โดยป้อนรายการทั้งเดือนล่วงหน้า ไม่ใช่การวัดความแม่นยำของการพยากรณ์ และช่วงข้อมูลเพียงเดือนเดียวจึงยังทดสอบการปรับแผนข้ามเดือนไม่ได้ แหล่งข้อมูลหลายเดือนที่เหมาะกับขั้นถัดไปอยู่ใน [DP_DATA_SOURCES.md](../DP_DATA_SOURCES.md)
